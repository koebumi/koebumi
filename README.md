# Koebumi

Koebumiは、macOSで使う音声入力アプリです。どのアプリでもFnキーを押して話すと、言いよどみや言い直しを取り除いた文章をカーソル位置に入力します。力を入れているのは、日本語の書き言葉に仕上げることと、Claude Code・Codexに声で指示できることです。無料で、ソースコードも公開中です。

日本語の仕上がりでは、句読点や表記を決まった規則でそろえます（〜して下さい → 〜してください、三時 → 3時）。くだけた話し方をしても、ビジネス敬語に直せます。人名の書き方は、画面に出ている表記が基準です。

Claude CodeとCodexは、声で操作できます。「スラッシュ コンパクト」と話すと/compactを入力し、許可の確認には「はい」や「いいえ、先にビルドだけして」と答えられます。文の最後に「送信」と言った場合は、Enterキーを押すところまでが自動です。話したファイル名は、作業フォルダにある実際の表記（`AgentInput.swift`）に直します。

APIキーがなくても使えます。その場合は、Appleのオンデバイスモデルや、このMacで動かす音声認識モデルを使うので、処理する場所はこのMacの中です。履歴・音声・辞書の保存先も、このMacの中だけです。

手持ちのAIで整形することもできます。ClaudeやOpenAI互換APIのキーのほか、ClaudeやChatGPTのサブスク（Claude Code・Codex経由）も使えます。

## 入れ方

必要な環境は、macOS 26以降のAppleシリコンのMacです。

1. [Releases](https://github.com/koebumi/koebumi/releases/latest)から`Koebumi-<版>.zip`をダウンロードして開く
2. 出てきたKoebumi.appを「アプリケーション」フォルダに入れて開く
3. 「開けませんでした」と出たら「完了」を押す。続けて、システム設定 > プライバシーとセキュリティを開き、下のほうにある「Koebumi」の「このまま開く」を押す
4. セットアップ画面に沿って、マイクとアクセシビリティを許可し、Fnキー（地球儀キー）を押したときの動作を変える

3の操作が必要なのは、まだAppleの公証を受けていないためで、行うのは最初の1回だけです。新しい版が出たときは、Koebumiが知らせます。Appleのオンデバイスモデルで整形するには、Apple Intelligenceをオンにしてください。

## 使い方

| 操作 | 既定のショートカット | 内容 |
|---|---|---|
| ディクテーション | `Fn` | 短く押すとハンズフリーになり、もう一度押すと確定します。押し続けて話すと、離したときに確定します（プッシュトゥトーク） |
| 翻訳 | `Fn + Left ⇧` | 話した内容を翻訳先の言語で入力します。翻訳先は音声バーで切り替えられます |
| Ask anything | `Fn + Space` | テキストを選択してから「もっと丁寧に」などと話すと書き換えます。選択中のテキストについて質問すると、カードで回答します。選択なしで質問した場合もカードで回答し、「YouTube で猫の動画」のような依頼ならページを開きます |
| 最後の結果を貼り付け | `Left ⌥ + Left ⌘ + V` | 直前の結果を、もう一度カーソル位置に入力します。キーをすべて離したときに貼り付けます |
| キャンセル | `Esc` | 録音・処理を止めます。回答カードも閉じます |

Fn を押したまま話している途中で Shift や Space を足すと、録音を続けたまま翻訳・Ask に切り替わります。ショートカットは設定画面で変更でき、1 つの操作に複数登録できます。

Finder（デスクトップ）で入力欄にフォーカスがないときに話すと、結果を貼り付けずにクリップボードにコピーします。

## ソースからビルドする

```sh
./scripts/build-app.sh            # build/Koebumi.app を作る（Apple Development 証明書で署名）
open build/Koebumi.app
# または ~/Applications に入れて起動する
./scripts/build-app.sh --install
```

初回起動時のセットアップ画面で、次の 3 つを行います。

1. マイクへのアクセスを許可する
2. システム設定 > プライバシーとセキュリティ > アクセシビリティ で Koebumi をオンにする
3. システム設定 > キーボード の「🌐キーを押して」を「何もしない」にする

以前の名前（Speak）で使っていた場合、設定・履歴・辞書・学習内容・API キーは初回の起動で Koebumi に写します（`Core/Storage.swift`）。API キーはキーごとにキーチェーンへのアクセスを確認されます。マイクとアクセシビリティは、アプリの識別子が変わったので許可し直してください。写し終えたら `~/Applications/Speak.app` と `~/Library/Application Support/Speak` は消して構いません。

必要な環境は macOS 26 以降（開発・確認は macOS 27）と Xcode 26 以降です。Apple のオンデバイス整形を使うには Apple Intelligence をオンにしてください。

この Mac で動かす音声認識モデル（MLX）の Metal シェーダーをビルドするため、初回だけ Metal Toolchain を入れてください（約 840 MB）。

```sh
xcodebuild -downloadComponent MetalToolchain
```

## Typeless の機能との対応

| Typeless の機能 | Koebumi での実装 |
|---|---|
| フィラー除去・繰り返し除去・言い直しの反映 | LLM で整形する（`AI/Prompts.swift`・`AI/Polisher.swift`）。「いや」「違う」「やっぱり」などの言い直しを検出して、言い直す前と後をモデルに明示する。質問に答えた・内容を落とした・言い直しを取り違えた・勝手に丁寧語にした出力は検出して 1 回やり直し、それでも駄目なら簡易整形にする。LLM が使えないときも正規表現でフィラーを除き、表記をそろえる |
| 表記の統一 | 音声認識が日本語に入れる空白（「明日は 9時」）、半角の「?」、全角英数字などを決まった処理で直す（`AI/TextCleanup.swift`）。この Mac のモデルが漢数字で書いた数は算用数字にする（三時 → 3時、三千万 → 3000万、一点五倍 → 1.5倍）。「一緒」「一時的」「十分です」「三日月」のような語は変えない（`AI/JapaneseNumbers.swift`） |
| 箇条書き・手順の自動整形 | 列挙を検出してリストにする。「改行」「新しい行」「段落」「新しい段落」「new line」などの音声コマンドにも対応。Apple の音声認識が捨てる日本語の「改行」は、DictationTranscriber を同時に動かして位置を拾う |
| アプリごとのトーン | 入力先アプリ（ブラウザはウィンドウタイトルの Gmail・Slack など）を 6 種類に分類する。種類ごとにトーンを指定でき、アプリの分類は上書きできる |
| パーソナライズ | 6 回話すごとに文体（丁寧さ・詳しさ・癖）を抽象的に学習する。進捗とレポートを表示し、オン・オフとリセットができる。内容そのものは保存しない |
| 個人辞書 | 手動追加、CSV の取り込みと書き出し、検索、絞り込み（すべて・自動・手動）、編集、削除。単語は音声認識のヒントと表記指定に使う。「聞き取られ方」（例: クロードコード → Claude Code）を登録すると、認識結果をその単語に置き換える |
| 辞書の自動追加 | 入力後 1 分以内にユーザーが単語を直すと、それを検出して辞書に追加し、直される前の語を聞き取られ方として覚える（`System/CorrectionWatcher.swift`）。入力欄を 1 秒ごとに読み、内容が変わらなくなったときに入力した直後のテキストと比べるので、語を消してから打ち直した直しや、かな漢字変換の途中は取りこぼさない。入力した文の部分だけを見るので、画面のほかの行が書き換わり続けても追える。端末（Ghostty など）では、入力した文がある画面（左右に並べた画面の 1 つ）だけを切り出し、折り返した行をつないでから比べるので（Claude Code のように右端を空けて折り返すアプリでは、入力した文がつながる幅を探す）、2 行以上の文や、直して行が増え画面が上にずれた場合も追える。1 回の入力で何語直しても、それぞれ登録する。打ちかけで登録した語（Claude Co）は打ち終えた語に置き換え、元に戻した直しは取り消す。名前と一緒に敬称なども書き換えたとき（棚香さん → 田中部長）は、聞き間違えた名前（棚香 → 田中）だけを登録する。登録するのは、読みが近い修正（急 → キュー、スレッドカン → スレッド間）と、カタカナを英字に直した修正（クロードコード → Claude Code）だけで、文を消して別の文を書いた変更、数を書き換えた変更（3時 → 4時）、敬称だけを書き換えた変更（鈴木さん → 鈴木課長）、文頭で大文字になっただけの英単語（Their → There）は登録しない。同音の漢字（公園 → 講演）は置き換えず、AI に文脈を見て直してもらう |
| 翻訳モード | 翻訳先リスト（並べ替え可）と、音声バーでの切り替え |
| Ask anything | 選択テキストの書き換え、質問への回答カード、カーソル位置への入力、Web ページを開く。Claude 使用時は Web 検索にも対応 |
| 100 以上の言語・自動判定・混在した発話 | この Mac のモデル（Qwen3-ASR・MOSS・Whisper）とクラウドの音声認識（OpenAI・Groq）は言語を自動判定する。Qwen3-ASR 1.7B と MOSS は、日本語の文に続けて英語の文を話しても両方を書き起こす。Apple の音声認識と Cohere は選んだ言語で認識し、録音中に切り替えられる |
| 言語のバリアント | 英語 US/UK、中国語 簡体/繁体、ポルトガル語 BR/PT などを選べる |
| 履歴 | 絞り込み（すべて・ディクテーション・Ask）、検索、コピー、フィードバック、再処理、音声のダウンロード、削除、すべて削除。保存期間は無期限・1年・1か月・1週間・24時間・保存しない から選べる |
| 統計 | 単語数、節約した時間、平均 WPM、連続日数、30 日間のグラフ |
| 設定 | マイク選択とテスト（自動検出では、既定のマイクが Bluetooth のイヤホンなら内蔵マイクを使う。ふたを閉じているときはイヤホンのまま）、インタラクションサウンド、入力中のミュート、表示言語（日本語・英語）、外観（アプリと音声バーで別々に選べる）、ログイン時に起動、Dock 表示 |
| プライバシー | 履歴・音声・辞書・学習内容はこの Mac の中だけに保存する。API キーはキーチェーンに保存する。新しい版の確認で 1 日 1 回 GitHub にアクセスする（設定 > 一般 でオフにできる） |

## Typeless にない機能

**日本語の仕上がり**（スタイル画面）
- 句読点を「、。」「，。」「，．」から選べます。英単語の前後の空白は、そのまま・入れない・入れるから選べます
- 補助動詞・形式名詞をひらがなで書きます（〜して下さい → 〜してください、出来る → できる、する事 → すること）。「資料を下さい」「出来事」のような本来の意味の語は変えません
- チャットに分類したアプリでは、句読点を付けない（初期値）・文末の句点だけ付けない・そのまま、から選べます。日本語・英語・中国語などどの言語にも効きます。「？」「！」と、1,000・3.5・a.m. のような数字と略語、箇条書きの番号（1.）は残します。翻訳した文では、句読点を付けない設定でも読点は残し、文末の句点だけを付けません（中国語は読点を消すと文が切れ目なくつながるため）
- アプリごとのトーンに「ビジネス敬語」を追加しました。くだけた話し方でも尊敬語・謙譲語に直します。二重敬語（おっしゃられる・ご覧になられる）は直します
- 表記は AI に任せず、入力する直前に決まった処理でそろえます。小さいオンデバイスモデルでも崩れません

**画面の文脈**（プライバシー画面。既定は「この Mac で処理するときだけ」）
- 録音を始めたときに、入力欄のカーソル前後と、同じウィンドウの文章をアクセシビリティ API で読みます（`System/SurroundingText.swift`）。読み取りは 1 回 0.15 秒・全体 0.3 秒で打ち切り、パスワード欄は読みません。読んだ内容は保存しません
- 敬称の前の名前を、読みが同じで画面に出ている表記に直します（渡辺さん → 渡邉さん、庄司さん・しょうじさん → 東海林さん）。読みは macOS の日本語解析で求めます。同じ読みの名前が画面に複数あるときは直しません
- 書きかけの文の続きとしてつなぎます。英語の空白と大文字小文字、重なった句点、カーソルの直前にある宛名の繰り返しを直します
- AI に渡すのは画面から拾った人名・用語の一覧だけで、文章そのものは渡しません。文章を渡すと、小さいモデルが画面内の指示に従ったり、書き写したりしたためです

**Claude Code・Codex**（スタイル画面の「アプリの種類」。既定はオン）
- 端末（Ghostty・Terminal・iTerm2 など）の画面に Claude Code や Codex が出ていたら、「AI チャット」として整形します。履歴のアプリ名は「Claude Code」「Codex」になります
- 見分けるのに使うのは画面の文字だけです（`System/CodingAgent.swift`）。Claude Code は横線で上下を挟んだ「❯」の入力欄、Codex は「›」の入力欄と、その下の「Context 0% used」や「? for shortcuts」の行で見分けます。Claude Code は許可の確認を出している間は入力欄を消すので、確認の形（1 桁下げた「Do you want to proceed?」と番号付きの選択肢、その下の「Esc to cancel」）でも見分けます。会話の中に同じ文字列が出ても、字下げされているので拾いません。プロセスを見ないので、herdr や tmux の中や、SSH 先で動いていても見分けられます
- 録音と並行して、端末の表示している範囲だけを読みます（Ghostty で約 30 ミリ秒）。読んだ内容は保存せず、AI にも渡しません
- AI には、話した内容がエージェントへの指示であることと、ファイル名・パス・コマンド・識別子を話したとおりに書くことを伝えます
- 「アプリの種類」で種類を指定した端末では見分けません
- herdr を使っているときは、herdr に選んでいる区画とその作業フォルダを聞きます（`System/AgentWorkspace.swift`）。左右に分けたシェルの区画に入力するときは、隣に Claude Code がいてもエージェントとみなしません。ウィンドウのタイトル（マシン名: ワークスペース名）が herdr に登録した SSH 先のマシンなら、そのマシンの herdr に聞きます（0.3〜0.4 秒。録音と並行して聞きます）。作業フォルダは、そのフォルダの `.claude` にある自作のコマンドを探すのに使います
- 話したファイル名を、作業フォルダにある実際の表記に直します（`AI/FileNameFixer.swift`）。作業フォルダのファイルは `git ls-files`（まだ追加していないファイルも含め、`.gitignore` のものは除く）で読み、1 分のあいだ覚えておきます。SSH 先では、コマンドを読むのと同じ 1 回の接続で読みます。「エージェントインプットを直して」は「AgentInput を直して」に、「パッケージドットスウィフト」は「Package.swift」に、「リードミーファイル」は「README ファイル」に、音声認識が英字で分けて書いた「agent input」は「AgentInput」になります。「アット ディクテーションコントローラー」と話すと、Claude Code でファイルを添付する形（`@Sources/Koebumi/Core/DictationController.swift`）にします。AI で整形する前に音の近さで決め、直した名前は AI に変えないよう伝えます。変更中のファイルの名前は、音声認識のヒントとして先に渡します
- 文の最後に「送信」と言うと、入力してから Enter を押します。「送信」だけを話すと、入力欄にある文を送ります。「データを送信」のように文の中で使った語は命令とみなしません
- 「スラッシュ コンパクト」「スラッシュ コードレビュー」のように話すと、AI で整形せずに /compact・/code-review と入力します。英語の名前は子音の並びで、日本語の名前のスキル（よみやす → /yomiyasu）は読みのローマ字で照らし合わせます。複数形のコマンドは単数でも呼べます（ワークフロー → /workflows）。音声認識が英語の名前を崩して英字で書いたもの（Grealmi・Giri me → /grill-me）も音で比べます。音声認識がカタカナ語の最後の「ト」を「と」にしたもの（コンテクスと送信）も直します。候補は組み込みのコマンドと、Claude Code の `~/.claude/skills`・`~/.claude/commands`（作業フォルダの `.claude` も）、Codex の `~/.codex/prompts` です
- Claude Code が許可の確認を出しているときは、「はい」「今後は聞かないで」「いいえ」「2番」と話すと、その選択肢を選びます。「いいえ、先にビルドだけして」のように続けると、No を選んでから続きを整形して入力し、送ります。選択肢の並びは確認の種類で変わる（No は Bash では 4 番、ファイルの作成では 3 番）ので、番号で言ったとき以外は選択肢の文で選びます。auto mode に切り替える選択肢は、番号で言ったときだけ選びます。「いや」は言い直しにも使う語なので、「いいえ」とはみなしません。短い返事は音声認識が別の字で書くことがある（いいえ → イエ・伊え、はい → Hi）ので、読みでも比べます。選択肢に当てはまらない文は入力せずに知らせます（入力すると、文の中の数字で選択肢が決まってしまうため）。キーは矢印と Enter で押します（数字のキーは、日本語入力がオンだと変換中の文字になって届かないため）。押す前に画面を読み直し、話している間にキーボードで答えていたら押しません。herdr では、選んでいる区画の画面だけを `herdr pane read` で読みます
- SSH 先で動いているエージェントでは、SSH 先の `~/.claude/skills` などを ssh で読んで候補にします（`System/RemoteFiles.swift`。1 回の接続で読み、1 分のあいだ覚えておきます）。SSH 先は、herdr の SSH 先のマシン、herdr の区画で動かしている `ssh`、端末で動かしている `ssh` から見つけます。パスワードは聞かない（BatchMode）ので、鍵でつなげるマシンだけで使えます。つなげないときは組み込みのコマンドだけを使います

**評価**（`eval/ja-cases.json`、Apple オンデバイス、15 ケースを 3 回ずつ）

| | 変更前 | 変更後 |
|---|---|---|
| 合格 | 12/45 | 42/45 |

## AI エンジン（BYOK）

設定 > AI エンジン で選びます。

**音声認識**

一覧から選びます。各モデルに速さと正確さの 5 段階評価、サイズ、言語を自動判定するかどうかを表示し、その場でダウンロード・削除できます（`UI/SpeechEngineList.swift`）。

- Apple オンデバイス（既定・キー不要・オフライン）。録音しながら逐次認識するので、話し終えてから約 0.5 秒で結果が出る
- この Mac で動かすモデル（キー不要・オフライン）。[speech-swift](https://github.com/soniqo/speech-swift) で Koebumi の中で直接動かす。重みは初回に Hugging Face から `~/Library/Caches/qwen3-speech/models/` にダウンロードする（`Speech/LocalSpeechModels.swift`・`Speech/LocalSpeechRuntime.swift`）
- OpenAI（`gpt-4o-transcribe`）
- Groq（`whisper-large-v3-turbo`）
- カスタム（OpenAI 互換の `/audio/transcriptions`。ローカルの Whisper サーバーなど）

この Mac で動かすモデルの比較（M3、macOS の読み上げ音声 9 本を 3 回ずつ認識した中央値の範囲。モデルの読み込みは含まない）

| モデル | サイズ | 1 回の認識 | 言語の自動判定 | 気づいた点 |
|---|---|---|---|---|
| Qwen3-ASR 0.6B（おすすめ） | 680 MB | 0.08〜0.24 秒 | する（30 言語） | 一番速い。辞書の単語を文脈として渡すと、その表記で書き起こす |
| Qwen3-ASR 1.7B | 2.1 GB | 0.16〜0.55 秒 | する（30 言語） | 日本語の文に続く英語の文も書き起こす |
| MOSS Transcribe Diarize | 1.0 GB | 0.63〜0.93 秒 | する | 日本語の文に続く英語の文も書き起こす。辞書の単語をホットワードとして渡す |
| Whisper Large v3 Turbo（CoreML） | 1.5 GB | 1.3〜1.9 秒 | する（99 言語） | 日本語と中国語に句読点が付かない。初回の読み込みは CoreML のコンパイルで約 20 秒かかる |
| Cohere Transcribe | 1.6 GB | 0.12〜0.31 秒 | しない（14 言語） | 音声バーで選んだ言語で認識する。日本語は最初の部分が抜けることがある |

選んだモデルは起動時に読み込み、別のエンジンやモデルに切り替えると手放します。ほかのモデルをダウンロードしている間も、選んだモデルは読み込んだままにします。

Qwen3-ASR では、録音を 30 秒以内の区間に区切って順に書き起こします（区切りは声の小さい箇所に置く）。一度に書き起こすと 448 トークンで切れ、15 秒を超えると同じ言い回しの 2 回目が崩れるためです。短い発話や無音で、文脈として渡した辞書や画面の語をそのまま書き出したときは、文脈なしで認識し直します。

**文章整形・翻訳・Ask anything**
- Apple オンデバイス（既定・キー不要）。整形は約 0.5〜1.5 秒
- Claude（`claude-opus-5-5` が既定。Sonnet 5.5 / Haiku 5.5 も選べる）。安全性フィルタで断られたときは、サーバー側で推奨モデルに切り替える `fallbacks: "default"` を有効にしている。Claude Max・Team プランに毎月付く API クレジットでも払える（claude.ai の設定 > Billing の API credits で Console の組織をつなぎ、その組織で作ったキーを使う）
- Claude のサブスク（Claude Code 経由）: この Mac の Claude Code を `claude -p` で動かし、Pro・Max のログインを使う（`AI/ClaudeCodeEngine.swift`）。Anthropic は他社のアプリが Claude.ai のログインやトークンを扱うことを認めていないので、Koebumi はトークンに触れず、ログインは Claude Code に任せる。ユーザーの設定・フック・MCP・CLAUDE.md は読ませない。呼ぶたびに起動するので、Haiku で 1 回 2〜3 秒（API より約 1 秒遅い）
- ChatGPT のサブスク（Codex 経由）: この Mac の Codex を `codex app-server` として常駐させ、ChatGPT のログインを使う（`AI/CodexEngine.swift`）。起動に約 1 秒かかるので、録音を始めたときに起動し、10 分使わなければ終了する。コマンド実行・プラグイン・メモリ・フック・MCP サーバーは起動時の設定で止める（`~/.codex/config.toml` は書き換えない）。`~/.codex/AGENTS.md` だけは止められず、指示に含まれる。1 回 3〜6 秒（gpt-6-luna で約 3.5 秒）
- OpenAI 互換: OpenAI、Groq、OpenRouter、Gemini、Ollama（ローカル・キー不要）、カスタム URL。モデル名とベース URL は書き換えられる
- 整形しない（簡易整形のみ）

## 制限事項

- 対応 OS は macOS だけです。Windows・Linux・iOS・Android 版と、端末間の暗号化同期はありません。
- Apple Private Cloud Compute は Apple の申請制 entitlement が必要なため使っていません。
- Web 検索は Claude（API キー）を選んだときだけ使えます。
- サブスクのエンジンは、Claude Code・Codex と同じ利用枠を使います。上限に達すると、戻るまで整形・翻訳もできません。OpenAI は、プログラムから Codex を使う場合は API キーを使うよう案内しています。ChatGPT のサブスクを Codex 経由で使う方法は公式の連携ではないので、OpenAI の方針が変わると使えなくなることがあります。
- Apple のオンデバイスモデルは小型なので、複雑な言い直しの解消や翻訳の自然さ、Ask anything での書き換えは Claude などに劣ります。長い発話（1,000 字以上）の整形には 10〜20 秒ほどかかります。
- Apple の音声認識は辞書のヒントを使わず、英語の語をカタカナで書きます。辞書の「聞き取られ方」に登録するか、AI 整形で直します。
- 表示言語は日本語と英語だけです。
- 画面の語を音声認識のヒントにしても、Apple の音声認識では効きません。効くのは Qwen3-ASR と MOSS、ヒントを使うクラウドの音声認識（設定で「クラウドの AI にも送る」を選んだとき）です。
- この Mac で動かすモデルは録音が終わってから認識するので、録音中に文字は出ません。ダウンロードは途中で取り消せません。
- speech-swift にはリリースのタグがないため、動作を確かめたコミットに固定しています（`Package.swift`）。
- 画面の文脈は、アクセシビリティ API で文字を公開しているアプリでだけ使えます（TextEdit と Safari で確認しました）。
- tmux などで端末を左右に分けていると、どの区画に入力するかは画面の文字からはわかりません。どこかの区画に Claude Code や Codex が出ていれば、シェルの区画に入力するときも AI チャットとして整形します（herdr では区画を見分けます）。
- 端末で直接 `ssh` しているときは、どのタブに入力しているかがわかりません。同じ端末でこの Mac のエージェントも動いていれば、この Mac と SSH 先の両方のコマンドを候補にします。tmux の中で動かしている `ssh` は見つけられません。
- SSH 先の作業フォルダの `.claude` にある自作のコマンドは、herdr の SSH 先のマシンでは herdr に聞いたフォルダで探します。それ以外では、SSH 先（Linux）で自分の Claude Code がみな同じフォルダで動いているときだけ探します。
- 声で答えられる許可の確認は Claude Code の「Do you want …?」だけです。Codex の承認、プランの承認（Would you like to proceed?）、Claude Code からの質問（AskUserQuestion）には答えません。herdr 以外で画面を左右に分けているときと、上下に分けて確認の下に別の区画が続いているときも答えません。どの区画に入力するかがわからず、シェルの区画で ↑ と Enter を押すと、前のコマンドをもう一度実行してしまうためです（herdr では選んでいる区画だけを見ます）。
- ファイル名を直すのは、git のリポジトリの中で動いているエージェントだけです（読むのは 5,000 ファイルまで）。「パッケージ」「インプット」のように 1 語の名前はふつうの言葉と見分けられないので、「ドット スウィフト」や「ファイル」を付けて話したときだけ直します。2 語以上をつないだ名前でも、「コーディングエージェント」のように一般的な言葉と同じ名前のファイルがあれば、その名前（CodingAgent）に直します。
- スラッシュコマンドは子音の並びで照らし合わせるので、綴りと発音が離れた英語（color → カラー）は見つけられないことがあります。音声認識が「スラッシュ」を崩して書いたとき（Thrash your simplified）も見つけられません。
- 端末（Ghostty など）で辞書の自動追加を使えるのは、どの行も同じ幅で画面を公開する端末だけです（Ghostty で確認しました）。入力してから 1 分の間に、ウィンドウの幅を変えたり、入力した文が画面の外に流れたりすると、そこで見張りをやめます。
